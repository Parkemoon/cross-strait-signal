# Frontend

React 19 + Recharts + Tailwind CSS 4. State management lives in `App.js`. All API calls use relative URLs (`API_BASE = ""`); dev server proxies `localhost:8000` via `"proxy"` in `package.json`.

## Chinese on the page — the rule

**Chinese appears only when it is the source's own words; UI chrome is English only.** Source text = headlines and key quotes as published, formulations on Positions (九二共識, with romanisation), poll option labels as the pollster printed them, topic codes (統獨), gazetted names (金門禁止水域, the MND 公告 zone names), a document's own title (CGA 表8-1, 護永專案), source names. Chrome = labels, captions, buttons, caveats, section intros, tooltips' explanatory text — never translated into Chinese. Why: on this site Chinese always means "this is what the source said"; a translated caption written by us has no source to anchor it, is reviewed by nobody, and drifts. Decided with Ed 2026-08-26 after the coast guard section briefly shipped bilingual caveats and captions (stripped; the `zh` fields in the API's `CAVEATS` remain available but are not rendered).

## Editable site prose (`src/copy.js` + `data/site_copy.json`)

Tier-1 copy — tab intros, section descriptions, reading cards, caveats, methodology paragraphs — lives in `data/site_copy.json` (flat key → string) and renders through `<Copy k="maritime.intro" fallback="…" vars={{latest_date}} as="div" style={…} />`. One `GET /api/copy/` per page load (module-level store shared by every `<Copy>`); in the admin build each block carries a ✎ that opens `CopyEditModal` → `PATCH /api/copy/{key}` → the store updates in place. **Adding a block = add the key to `site_copy.json` FIRST, then reference it**; `tests/test_site_copy.py` fails on any `<Copy k=…>` whose key is missing (a missing key would otherwise silently render the fallback). Keys are pre-declared server-side too: `PATCH` 404s on an unknown key, so renames are a code change. Plain text only — blocks with links (source footers) stay in JSX; labels/buttons/axis titles (Tier 2 chrome) stay in code. The coast guard caveats' TEXT is here (`coast_guard.caveat.<key>`), their scope stays in `api/routes/coast_guard.py` (`CAVEAT_SCOPES`). Edits land on the server's copy of the file (prod when editing prod) — same sync dance as `positions.json`: copy prod → staging before content changes, commit together. `lead="Scale caveat:" leadColor=…` renders a bold label before the text (the one inline-markup case prose blocks need); other inline emphasis was dropped in the migration — plain text is the contract. **Migrated (2026-08-26, 42 keys)**: Maritime + Coast Guard, Military (intro, ADIZ explainer, vessels note, exercises intro, map note), Indicators (intro, investment summary/gap/scale caveat, macro intro), Trade Access (sources), People (intro, chart notes, methodology, sources), Diplomacy (intro), Positions (page + concepts intros), About (every paragraph except the bio/GitHub lines). Still in JSX by design: blocks that are mostly links (Trade Access intro, Economy sources footer, Diplomacy basemap credits, Military sources footer, About bio/source-code lines) and all Tier-2 chrome.

## Central API client (`api.js`)

Every fetch in the frontend goes through a named function in `api.js`, not inline `fetch`. When adding a new API endpoint, add the corresponding function to `api.js` first; components import from it directly.

`fetchStats` only forwards keys in `SCOPING_KEYS` to the stats endpoint (`sentiment` and `search` are intentionally article-list-only). When adding a new scoping filter, add it to both `SCOPING_KEYS` here AND `_build_filter_clause` in `stats.py`.

## Read-only build (`readOnly.js`)

`READ_ONLY = process.env.REACT_APP_READ_ONLY === 'true'`. Import in any component with write controls to hide them in the public build. Build with `npm run build:public` (sets `BUILD_PATH=build-public`). Nginx also blocks POST/PATCH on the public server at the edge.

## Layout and view state (`App.js`)

- **Navigation is data-driven** (2026-08-26): `src/navGroups.js` is the single source of truth — `NAV_GROUPS` = Feed · **Security** ▾ (Military, Maritime) · **Economy** ▾ (Indicators = `EconomyTab`, Trade Access, People) · **Politics** ▾ (Polls, Diplomacy, Positions[admin-gated]) · **Admin** ▾ (Review, Alt Models; admin build only). `components/NavMenu.jsx` renders it as desktop dropdown buttons (hover/click; clicking the group of the current view returns to the feed; the active sub-view shows as a caption under the group label; Review count badges the Admin group) and as the mobile two-level sticky bar (groups + Stats/Social → tap a group → its items with a `‹` back). **Adding a tab = one entry in `NAV_GROUPS` + a render branch in `App.js`**; `WIDE_VIEWS` (every non-feed view) drives the layout collapse automatically. Group placement is framing: Maritime sits BESIDE Military under Security because coast guards are law enforcement, not military.
- `view` state (`"feed"` | any view id in `navGroups.js`) controls the center column on desktop. `"review"` → `<ReviewQueue />`; `"economy"` → `<EconomyTab />`; `"trade"` → `<TradeAccessTab />`; `"people"` → `<PeopleTab />`; `"military"` → `<MilitaryTab />`; `"maritime"` → `<MaritimeTab />`; `"polls"` → `<PollsTab />`; `"diplomacy"` → `<DiplomacyTab />`; `"positions"` → `<PositionsTab />` (nav entry + render gated `!READ_ONLY` until the curated content is reviewed — flip `adminOnly` in `navGroups.js` to take it public).
- The 3-column grid collapses to 2 columns (hides the Social Pulse right aside) when `view` is in `WIDE_VIEWS`, so wide tables/charts/maps get full width.
- Below 768px (`isMobile`, from `hooks/useWindowWidth.js`), everything collapses to a single column with the sticky `NavMenu mobile` bar (`mobileTab` state; `feed`/`stats`/`social` share the feed view). Each panel shows/hides via `display: none`. Check `isMobile` when adding any fixed-width or multi-column structure.

## Sync points — keep these in lockstep when adding things

| Adding | Update |
|---|---|
| A scoping filter | `SCOPING_KEYS` (api.js) + `_build_filter_clause` (stats.py) + `hasScopingFilter`/`buildScopeLabel` (StatsSidebar) |
| A new source place | API filter block in `articles.py`; never hardcode beyond PRC / TW / hk / intl in `FilterBar` |
| A multi-feed publication | `PUBLICATION_NAMES` (StatsSidebar source grouping) + `SOURCE_FILTER` (click-to-filter prefix map) + `SOURCE_ABBREV` (SourceBadge) |
| A TW-vs-PRC pair on Economy tab | `MACRO_PAIRS` in `EconomyTab.jsx` (set `dualAxis: true` when scales differ ≥5×) |
| A verification reporter pair | `VERIFICATION_PAIRS` (economy.py) + `VERIFICATION_KINDS` (EconomyTab.jsx) for subsection styling |
| A new industry that misses bar colour | Widen the `INDUSTRY_SECTOR` token list in EconomyTab.jsx or accept grey "Other" |
| A new trade-access direction or status | `DIRECTIONS` / `STATUS_FILTERS` / `STATUS_PILLS` in TradeAccessTab.jsx |
| A new economic indicator | `SERIES_META` in `api/routes/economy.py` with a `category` field — picker auto-discovers via `data.series` (except `category='macro'`, which is filtered out and goes through MacroSection instead) |
| A new metric for `cross_strait_population` | Update the seed script or scraper to produce the metric; `PeopleTab.jsx` pulls a small fixed set of metrics (latest residence permit, census, spouse stock, 台胞证 holders) so add a KPI card and/or chart for new metrics that should be surfaced |

## Component-specific notes

- **`StatsSidebar.jsx`**: dashboard gauges sorted PRC → TW → HK/Macao → International. Taiwan camp gauges (`green` / `green_leaning` / `blue`) hidden below n=5 articles to avoid noise. When a scoping filter is active, a teal chip appears above "Strait Watch" with a dismissable `×`; each gauge shows a grey ghost dot at the global baseline position (only when scoped score differs by >0.01). `TopicBreakdownChart` hides when `filters.topic` is set. All sidebar elements are clickable to set filters: gauges → `onPlaceClick(placeKey|null)`, camp gauges → `onBiasClick(bias)`, source rows → `onSourceClick(dbPrefix)` using `SOURCE_FILTER` map, entity rows → `onEntityClick(entityNameEn)`. Renders `<StatSpotlight onOpen={onOpenTab} />` between the topic breakdown and Sources sections; `onOpenTab(view)` is the generic tab-switch callback from `App.js` (replaced the old economy-only `onOpenEconomy`).
- **`StatSpotlight.jsx`**: rotating single-slot sidebar widget — one card cycles a headline figure from each top-level section (Economy trade balance → PLA 30-day ADIZ avg → NCCU Taiwanese-identity % → PRC ECFA suspensions → monthly cross-strait visitor flow). Each slide-builder deliberately picks the *freshest* meaningful figure its section exposes — e.g. People uses the monthly visitor flow, not the spouse/permit stocks which lag years (the NIA 13503 spouse resource is frozen at 2020). Replaced the old static `EconomyMini`; economy is slide 0 so first paint is unchanged. Fetches all five section summaries in parallel on mount (`Promise.allSettled`), each via a per-section *slide-builder* that returns `null` when its data isn't ready, so a slow/empty section silently drops out of the rotation. Auto-advances every `AUTO_MS` (7s) with pause-on-hover/focus and pause-when-offscreen (IntersectionObserver — also covers the mobile `display:none` collapse); honours `prefers-reduced-motion` (no auto-advance). Dot nav steps manually + re-arms the timer via `cycleNonce`. Whole card + "More →" call `onOpen(view)`. The poll slide matches the "Taiwanese" option by **label** (`label_en === "Taiwanese"`), not position. Self-contained formatters (`formatUsdB`/`formatCount`/`DeltaChip`) — does NOT import EconomyTab's (kept decoupled). To retune which stat a section surfaces, edit that section's slide-builder.

## Build env caveat

Never run `npm run build` (admin bundle) without sourcing `.env` — the admin bundle bakes in `REACT_APP_ADMIN_TOKEN` at build time. A plain `npm run build` ships an empty token; every write request then fails auth.

For iterating fast: `set -a && source .env && set +a && cd frontend && REACT_APP_ADMIN_TOKEN="$ADMIN_TOKEN" npm run build`. Otherwise use `bash server_deploy.sh` which handles env sourcing. The public build (`npm run build:public`) intentionally has no token and is safe to run without env.

## Alt-model experiment components (admin-only)

- **`AltModelPanel.jsx`**: comparison strip inside `ArticleCard`'s expanded detail, mounted `{!READ_ONLY && ...}` next to Analyst Commentary. Fetches `/api/alt-models/article/{id}` on mount (cards fetch only when expanded); renders NOTHING when the article hasn't been swept, so unswept feeds stay visually unchanged. Reuses `TopicPill`/`SentimentBadge` (production palette); arm chips neutral grey / originator red / control blue; `refused` renders as a red FILTERED/REFUSED finding block, not an error state.
- **`AltModelsTab.jsx`**: aggregate view (view id `altmodels`, desktop button + mobile tab both gated `!READ_ONLY` — permanent admin view, not a pre-ship gate like Positions). Summary cards per (model, arm) + refusal browser, plus a "How to read these numbers" definitions block (topic agreement / |Δscore| / signed bias / refusal-rate caveat) and a "Findings" section distilled from `ALT_MODEL_EXPERIMENT_WRITEUP.md` — the findings text is the FROZEN 2026-08 dataset, the cards are live, so headline figures can differ a few points (deliberate; the block says so). The gemini-control card carries a "noise floor" chip (same-model rerun ≈ the agreement ceiling). **Retired models** (Kimi K3) are hidden from the tab, refusal browser, the feed lens AND the per-article `AltModelPanel` via `RETIRED_MODELS`/`isRetiredModel` in `src/altModels.js` — presentation-side only, sweep rows stay in the DB for reproducibility. Footer discloses the two methodology caveats (approximated decoding config; sanitised answers classify `ok`).
- **`AltModelLens.jsx`**: admin-only feed toggle rendered between the Signal Feed header and `FilterBar`. Three-way segmented control — **Gemini only** (production feed, lens off) / **\<model\> only** / **Both** — plus a (model, arm) combo dropdown that only appears when more than one combo has sweep rows (from `/api/alt-models/summary`; renders nothing when no sweeps exist). Selection flows `App.js` `altLens` (`{model, arm} | null`) + `altDual` (bool, display-only — kept outside `altLens` so toggling Both doesn't refetch) → `useDashboardData` → `alt_model`/`alt_arm` params on `/api/articles`, narrowing the feed to swept articles with `alt_*` fields attached. In `ArticleCard`: **model-only** swaps topic pill / sentiment badge / reasoning / summary to the alt model's output with no Gemini chrome except a compact amber `≠ Gemini` marker when the topic diverges; **Both** keeps production primary (topic click-to-filter stays live) with the alt model's pill+badge in a labelled inline group (amber-bordered on topic divergence) and its summary+reasoning in a read-only block below the production summary. Under any active lens the cards get the model's background tint (`MODEL_TINTS`/`modelTint`/`modelTintRgba` in `src/altModels.js` — stronger in model-only than Both) so a lensed feed is never mistaken for production. Non-`ok` outcomes render as a finding chip (red for refused, grey for parse/API errors) alongside the production badges; the alt summary is deliberately NOT wrapped in `FieldEditor` (overrides must never write model output into production); the topic pill's click-to-filter is disabled under model-only (filters run on production values server-side). Headline/quote translations always stay production — sweeps don't retranslate. Label + tint maps shared via `src/altModels.js` (`MODEL_LABELS`/`ARM_LABELS`/`MODEL_TINTS`) — add new sweep models there once. The lens also flows into `fetchStats` (which sends `authHeaders()` — the lens params are admin-gated), so the **sidebar re-aggregates from the sweep too**: `StatsSidebar` renders a tinted banner naming the (model, arm) whenever the response's `alt_lens` echo is set — it keys off the server echo, never client state, so the banner can't disagree with the numbers. Under **Both** (`altDual` prop) the sidebar overlays the response's `alt_baseline` (production Gemini over the same swept subset): gauges reuse the ghost-dot mechanism (ghost = Gemini), and `SentimentTrendChart` takes optional `baseline` (dashed grey Gemini line) + `accent` (model tint recolours the main line — also applied in model-only mode); its tooltip selects payload entries by dataKey, not position. Sidebar 30-day window still applies under the lens — a sweep of old articles shows an empty lensed sidebar.
